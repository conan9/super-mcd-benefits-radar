# 隐私边界与公开发布范围

本文件说明两件事：

1. 本技能在**运行时**如何处理凭据与个人信息；
2. 本**公开仓库**为什么不含真实响应、以及发布前做过哪些检查。

---

## 1. 运行时的凭据与隐私处理

| 对象 | 处理方式 | 技术落点 |
|---|---|---|
| MCP Token | 只从环境变量 `MCD_MCP_TOKEN` 读取；不写入任何文件、不回显、不放进 URL / query string | `mcd_client.py` |
| 请求头 `Authorization` | 仅放入 HTTP 头；日志、异常、报告统一经 `redact()` 遮蔽 | `redact()`，规则见下 |
| 会员标识 `accountId` | 归一化时**丢弃取值**，只记录"字段存在过"；不进数据结构、不进报告、不进日志、不进 `--dump-raw` | `normalize_account()` |
| 带签名的素材 URL | 视为**有时效凭据**，导出时掩码（键名保留、取值替换） | `mask_sensitive()` |
| 手机号 | 本项目不采集、不存储、不输出手机号 | — |

`redact()` 的规则（宁可过度遮蔽，也不放过一枚 Token）：已知密钥精确替换 →
`Bearer <...>` → JSON 中 `authorization` / `token` / `apiKey` / `secret` 等键的值 →
`sk_` / `pk_` / `key_` / `token_` / `secret_` 前缀密钥 → 32 位以上连续十六进制 →
40 字符以上 base64url 串。后两条**刻意不加词边界**，因为开发中确实漏掉过
`sk_live_<长十六进制>` 形态的密钥（`_` 之后不成立 `\b`）。

回归用例：`tests/test_redaction.py`、`tests/test_submission_ready.py`。

## 2. 公开仓库为什么不含真实响应

`query-my-coupons`、`query-my-account`、`available-coupons`、`campaign-calendar`
四个工具的真实返回**含账户数据**（券清单、积分余额）。它们的**格式结构**是
本项目必须面对的客观事实，但**取值属于账户信息**。

因此公开发布版采取的做法是：

| 处置 | 对象 |
|---|---|
| **不纳入** | 真实响应的逐字副本（券清单、积分记录） |
| **不纳入** | 由真实数据生成的报告、活动板块渲染样例、真实调用记录原文 |
| **不纳入** | 任何 Token、Authorization 实值、手机号、账号标识取值、调试日志、临时数据 |
| **保留** | 工程结论（格式、解析率、缺陷与修复）——见 [`live-verification.md`](live-verification.md) |
| **替换** | `fixtures/` 四个响应样例 → **逐行结构同构、取值全部合成**（券名/活动名带 `【合成样例】` 前缀） |

合成样例不是"编造数据"，而是**把取值换成明显的占位值**：
结构、层级、字段标记、行尾续行、日期分组一律逐行保留，因此
解析器面对的是真实格式，测试仍然有意义。判定依据是**行内可见的标记**
（`【合成样例】` 前缀），不会与真实数据混淆。

## 3. 发布前安全检查清单

| # | 检查项 | 方法 |
|:---:|---|---|
| 1 | 无真实 Token / Authorization 实值 | `tests/test_submission_ready.py::test_no_credentials_in_repo` 全仓扫描 |
| 2 | 无中国大陆手机号 | 同上（正则含边界，避免把 13 位时间戳误判） |
| 3 | 无账号标识取值 | 同上 + `tests/test_account_payload.py::TestPrivacy` |
| 4 | 配置示例只含占位符 | `test_example_config_uses_placeholder` |
| 5 | 响应样例不含签名参数 | `test_replay_pipeline.py::test_replay_fixtures_themselves_are_clean` |
| 6 | 报告不出现 Token / 账号取值 | `test_replay_pipeline.py::TestNoSensitiveLeakage` |
| 7 | 无绝对路径 / 依赖原开发目录 | 全仓正则扫描 + 全新目录解压后独立跑通 |
| 8 | 不打包任何本机 WorkBuddy 连接器配置或缓存 | 发布目录仅由源码文件构成，逐文件清单核对 |
| 9 | 不使用未审查的 Git 历史 | 公开仓库使用**干净的初始提交**（见下） |
| 10 | 官方声明未被改动 | `CONTEST_DECLARATION.md` 按 MD5 + 字节数 + 换行符三重锁定 |

### 关于 Git 历史

公开仓库从**一次干净的初始提交**开始，不继承任何开发期的历史。
理由很直接：开发期的提交里出现过含真实响应的中间产物，
即使后来删除，旧提交仍可被检出——**唯一的稳妥做法是不继承这些历史**。

## 4. 本技能不做什么

* **不下单、不领券、不兑换积分、不抽奖。** 写入类工具在代码层被
  `READ_ONLY_TOOLS` 白名单拦下（**默认拒绝**），不是文档约定。
* **不代用户执行任何写操作**，只输出排序与建议，执行权留给人。
* **不把"读不懂"伪装成"没有数据"**。解析失败必须显式报警。
* **不预测**券的发放、价格变动或积分过期规则。
